# 隐私与数据边界

## 本机保存的内容

默认数据目录是 `%LOCALAPPDATA%/Dockyard`。其中包含工作区配置、资源名称与路径、
文件夹索引、配色、字体信息、规则正文、桌面偏好、截图缓存与笔记。
这些内容可能敏感，不属于项目演示数据，不应提交到 GitHub 或随安装包分发。
卸载保留资源数据；删除应用不等于删除数据。

## AI 可以取得什么

- `context`：当前工作区、已启用组件摘要、数量和索引状态。
- `search`：匹配资源的引用、名称和匹配原因等摘要。
- `get`：文件路径与可用状态、颜色值、字体信息或规则正文等具体资源数据。

MCP 只查询当前工作区启用的资源，不读取文件正文，也不改写素材。
文件夹索引在添加、变更来源或手动刷新时生成；查询不代表实时扫描全部文件。
AI 客户端可以依据返回路径，在其自身权限下读取文件。

返回结果可能被 AI 客户端发送给模型服务。因此，“本地保存”不代表“所有数据
绝不离开本机”。启用资源前，应确认其名称、路径、规则及关联内容适合交给所用客户端。
笔记目前仅供桌面使用，不加入 MCP 查询。

## 连接与截图

连接 Codex 经确认后修改其配置，并在用户的 Codex 目录保存备份。备份可能包含
原有敏感设置，不要上传完整配置或备份文件。独立 MCP 自检不等于真实模型已成功调用。

截图会进入本机缓存和剪贴板，可能包含其他应用的信息。公开反馈时请使用演示
工作区，并检查图片、窗口标题、用户名、路径和通知内容。

## 项目检查

`npm run privacy:check` 检查当前受版本控制或未忽略的文本文件，输出文件位置，
不输出疑似秘密的值。它不是完整秘密扫描器，不覆盖 Git 历史、压缩包和二进制内容。
公开前还需独立检查全部历史及最终分发文件。

`npm audit` 会向 npm 审计服务发送依赖名称与版本。本项目的 CI 也会执行它；
提交私有依赖前应评估是否允许这项传输。
