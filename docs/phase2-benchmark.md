# Phase 2 性能与验收记录

测量时间：2026-09-25。执行命令：`npm run bench:search`。完整机器可读结果写入 `.local/phase2-benchmark.json`（忽略提交）。

## 环境与方法

- Windows 10.0.19045 x64，Node v24.13.1。
- AMD Ryzen 7 3700X，16 个逻辑核心，约 31.94 GiB RAM。
- 30,000 条合成 Folder 索引记录，从磁盘 JSON 加载；8 类查询包括精确 ID、完整 ref、中文、双关键词、常见扩展名与无匹配查询。
- 独立子进程执行冷查询，冷查询包含 JSON 读取/校验、资源投影和搜索字段预处理；单独记录模块导入时间。没有清空操作系统磁盘缓存。
- 热查询预热 8 次后顺序采样 160 次，包括每次配置一致性检查、索引身份检查、排序及响应大小校验。
- 内存为进程 RSS/heap 采样值，不是操作系统记录的绝对峰值；每个 MCP 进程有独立缓存。

## 行为验收

npm test：53 项全部通过。真实 Codex 的 search/get 完成事件均验收通过。完整回归覆盖首次扫描、前导零、重复 ID、无 ID 文件、中文别名、确定性排序、最多 10 项、按实际 MCP 序列化字节裁剪、Workspace 范围、热更新及调用方无法修改内部缓存。

刷新测试覆盖：

- 新增文件刷新后出现；删除文件先返回 missing，刷新后退出索引。
- 刷新暂停期间查询旧快照，发布后读取新快照。
- 根目录丢失或拒绝访问时保留旧快照并记录失败；局部目录拒绝访问时返回 partial。
- 来源配置在扫描中改变会放弃发布；查询不会复用其他来源的旧索引。
- 跳过目录链接、junction、数据目录、.git、node_modules；保留普通隐藏素材。
- 索引后将目录替换为越界 junction，get 返回 inaccessible。
- MCP 查询不会调用目录枚举；get/search 不返回素材正文，search 不返回 Instruction 正文。
- 两个真实 stdio MCP 子进程能读取同一刷新结果与 Workspace 切换。

这些结果反映本机当前运行环境；后续桌面阶段仍需验证界面响应与较大库的内存表现。
