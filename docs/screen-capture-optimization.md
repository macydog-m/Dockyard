# 屏幕工具延迟与缩放修复（2026-09-25）

用户反馈：进入吸色或截图需要等待，画面会缩放、跳动。

## 原因与证据

不是开发版独有的问题。开发版与安装包使用同一个屏幕捕获模块。

在本机两台 2560 × 1440、125% 缩放显示器上，单个显示器的逻辑尺寸为 2048 × 1152，但旧覆盖层内容区域实际是 2052 × 1115。Windows 在创建普通无边框窗口时将高度限制到工作区，且默认 thick frame 带来额外边框尺寸。旧代码把 2560 × 1440 截图拉伸到这个不匹配的画布，既造成视觉跳变，也让画布预览坐标和主进程裁剪坐标不一致。

旧启动流程还有固定 200ms 等待、每次顺序创建两个 BrowserWindow、两张全屏 PNG/Base64 编码及前端图片解码。页面 load 完成后立即显示，没有等待画布绘制完成。

基线记录：`output/playwright/capture-baseline.json`。双屏全部可见时的三次耗时为 1497 / 1396 / 1411ms。

## 修改

- `thickFrame: false`；创建后显式设置完整显示器 bounds，隐藏状态下完成定位，不调用系统全屏切换。
- 启动后只预热隐藏 UI；实际抓屏仍在用户点击后进行。重复使用同一组覆盖层，结束时清除主进程整屏引用与前端画布像素。
- 隐藏工具条后的等待缩短为 32ms，首次窗口准备与屏幕抓取并行。
- IPC 传递 BGRA 像素，前端一次转换为 RGBA，省去整屏 PNG/Base64 编解码。用户选中的截图仍按 PNG 保存。
- 每块屏幕完成绘制、确认视口尺寸后统一显示，避免旧帧、黑帧和中间尺寸被用户看到。
- 用每个覆盖层确认的视口计算最终取色和截图坐标；会话序号拒绝上一次操作的迟到消息。
- 显示器布局或 DPI 变化时取消当前操作、重建隐藏覆盖层。

## 验证

优化后同一台机器、同样三次测量：817 / 658 / 640ms，中位数从 1411ms 降至 658ms，约减少 53%。记录在 `output/playwright/capture-optimized.json`。剩余开销主要是 Electron/系统抓屏（该次约 463–581ms），此结果不是所有设备的性能保证。

新增 `scripts/screen-capture-regression.mjs`：

- 两块屏幕（含负坐标副屏）的原生内容 bounds、前端视口与显示器一致。
- 在每块屏幕底部放置 20px 小色块，验证显示的像素和最终返回色值相同。此位置能检出旧版垂直缩放偏差。
- 连续操作复用相同覆盖层窗口；结束后像素清空；过期会话无权提交。
- 截图取消后工具条恢复；模拟抓屏失败后下一次操作正常恢复。

另外通过 `scripts/widget-smoke.mjs`（真实吸色、截图复制、PNG 保存、加入工作区）与 `scripts/desktop-smoke.mjs`（原有资源及 MCP 流程）。具体打包版结果见 `output/playwright/screen-capture-regression.json`。

当前验证覆盖双屏相同 125% DPI；混合 DPI 与动态拔插物理屏幕尚未实测。
